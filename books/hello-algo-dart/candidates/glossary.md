# 《Hello 算法》术语表（Dart 版）

> 来源：靳宇栋《Hello 算法》2026 Release 1.3.0 · 术语取自 16.3 术语表及全书章节

---

## 一、核心概念

### 算法（Algorithm / 演算法）
算法是一组在有限时间内解决特定问题的一系列明确操作指令。可通过有限步骤将输入转化为输出，不依赖于特定编程语言实现。
- 关联：数据结构、复杂度分析、程序
- 首次出现：1.2.1

### 数据结构（Data Structure / 資料結構）
计算机组织和存储数据的方式，定义了数据的逻辑关系和物理存储形式。旨在高效地访问和修改数据。
- 关联：算法、逻辑结构、物理结构
- 首次出现：1.2.2

### 复杂度分析（Asymptotic Complexity Analysis / 渐近复杂度分析）
评估算法效率的理论方法，用数学函数描述算法时间/空间开销随数据规模增长的趋势，消除实际测试的环境差异。
- 关联：时间复杂度、空间复杂度、大 O 表示法
- 首次出现：2.1.2

## 二、复杂度衡量

### 时间复杂度（Time Complexity / 時間複雜度）
衡量算法运行时间随输入规模 n 增长的趋势。不统计具体运行秒数，而是统计基本操作数量 T(n) 的渐近增长级别。
- 关联：大 O 表示法、渐近上界、空间复杂度
- 首次出现：2.3

### 空间复杂度（Space Complexity / 空間複雜度）
衡量算法运行过程中占用内存空间随输入规模 n 增长的趋势，分为输入空间、暂存空间、输出空间。通常以最差输入和最差运行时刻为准。
- 关联：时间复杂度、大 O 表示法、内存
- 首次出现：2.4

### 大 O 记法（Big-O Notation / 大 O 記號）
表示函数渐近上界的数学符号，记作 O(f(n))。表示当 n 趋向无穷时，T(n) 的增长不会超过 f(n) 的常数倍。最差时间复杂度通常用大 O 表示。
- 关联：渐近上界、时间复杂度、空间复杂度
- 首次出现：2.3.2

### 渐近上界（Asymptotic Upper Bound / 漸近上界）
当输入规模 n 趋于无穷大时，算法操作数量 T(n) 的增长率被某个函数 f(n) 的一个常数倍从上方封顶，即 T(n) = O(f(n))。
- 关联：大 O 记法、时间复杂度、增长趋势
- 首次出现：2.3.2

### 最差/最佳/平均时间复杂度
最差：最不利输入下的复杂度；最佳：最有利输入下的复杂度；平均：随机数据输入下的期望复杂度，最接近实际应用性能。
- 关联：时间复杂度、大 O 记法、输入分布
- 首次出现：2.3.5

### 常数阶 O(1)（Constant Order）
操作数量与输入数据大小 n 无关，不随 n 变化。例如访问数组的某个元素、单次数值运算。
- 关联：时间复杂度、线性阶、对数阶
- 首次出现：2.3.4

### 线性阶 O(n)（Linear Order）
操作数量随 n 线性增长，通常出现在单层循环遍历中。
- 关联：时间复杂度、常数阶、平方阶
- 首次出现：2.3.4

### 平方阶 O(n²)（Quadratic Order）
操作数量随 n 平方级增长，常见于嵌套循环。
- 关联：时间复杂度、线性阶、指数阶
- 首次出现：2.3.4

### 指数阶 O(2ⁿ)（Exponential Order）
操作数量随 n 指数增长（如细胞分裂），常见于二叉树、组合枚举等。增长极快，应尽量避免。
- 关联：时间复杂度、对数阶、阶乘阶
- 首次出现：2.3.4

### 对数阶 O(log n)（Logarithmic Order）
操作数量随 n 对数级增长，每次操作将问题规模缩小一半。典型如二分查找。
- 关联：时间复杂度、线性对数阶、二分查找
- 首次出现：2.3.4

### 线性对数阶 O(n log n)（Linear-Logarithmic Order）
操作数量为 n 乘以 log n 级别，常见于高效的排序算法如归并排序、快速排序。
- 关联：时间复杂度、对数阶、归并排序
- 首次出现：2.3.4

### 阶乘阶 O(n!)（Factorial Order）
对应全排列问题的复杂度。n 个互不重复元素的排列方案数为 n!，增长极快。
- 关联：时间复杂度、指数阶、全排列问题
- 首次出现：2.3.4

## 三、基础数据结构

### 数组（Array / 陣列）
连续内存空间中存储同类型元素的线性数据结构。通过索引实现 O(1) 随机访问，但插入/删除需移动元素（O(n)），初始化后长度固定。
- 关联：链表、索引、随机访问、动态数组
- 首次出现：4.1

### 索引（Index / 索引）
数组中每个元素的编号，从 0 开始。通过 `数组地址 + 元素长度 × 索引` 实现 O(1) 定位。
- 关联：数组、随机访问
- 首次出现：4.1.1

### 链表（Linked List / 鏈結串列）
节点通过指针（引用）串联而成的线性数据结构。节点分散存储在内存中，支持 O(1) 插入/删除，但访问需遍历 O(n)。
- 关联：数组、链表节点、头节点、指针
- 首次出现：4.2

### 链表节点（Linked List Node / 鏈結串列節點）
链表的基本单元，包含数据值 val 和指向下一节点的引用 next。
- 关联：链表、头节点、尾节点、指针
- 首次出现：4.2

### 头节点 / 尾节点（Head Node / Tail Node）
链表的首节点（头节点）用于定位整个链表；链表末尾节点（尾节点）的 next 指向 null，表示链表结束。
- 关联：链表、链表节点
- 首次出现：4.2

### 动态数组（Dynamic Array / 動態陣列）
在普通数组基础上支持动态扩容。当元素数量超过容量时，自动分配更大的内存空间并迁移数据。
- 关联：数组、列表
- 首次出现：4.3.2

### 列表（List / 串列）
支持增删查改的有序元素集合，基于动态数组或链表实现。Dart 中 List 类默认基于动态数组。
- 关联：动态数组、数组、链表
- 首次出现：4.3

### 栈（Stack / 堆疊）
遵循后进先出（LIFO）的线性数据结构。只能在栈顶执行入栈 push 和出栈 pop 操作，类似一叠盘子。
- 关联：队列、栈顶、栈底、LIFO
- 首次出现：5.1

### 栈顶 / 栈底（Top / Bottom of Stack）
栈的操作端称为栈顶（唯一可操作位置），另一端称为栈底。入栈和出栈均在栈顶进行。
- 关联：栈、队列
- 首次出现：5.1.1

### 队列（Queue / 佇列）
遵循先进先出（FIFO）的线性数据结构。元素从队尾入队，从队首出队，类似排队。
- 关联：栈、队首、队尾、双向队列
- 首次出现：5.2

### 队首 / 队尾（Front / Rear of Queue）
队首为出队端（最先进入的元素），队尾为入队端（最新加入的元素）。
- 关联：队列、入队、出队
- 首次出现：5.2.1

### 双向队列（Double-Ended Queue / 雙向佇列）
同时支持在队首和队尾两端进行入队和出队操作的队列，兼具栈和队列的功能。
- 关联：队列、栈
- 首次出现：5.3

## 四、哈希表

### 哈希表（Hash Table / 雜湊表）
通过哈希函数将键 key 映射为数组索引从而实现快速访问的键值对数据结构，查询/插入/删除均为 O(1)。
- 关联：哈希函数、桶、哈希冲突、键值对
- 首次出现：6.1

### 哈希函数（Hash Function / 雜湊函式）
将任意键 key 映射到固定范围整数（数组索引）的函数。好的哈希函数应计算高效且分布均匀。
- 关联：哈希表、哈希冲突、桶
- 首次出现：6.1

### 桶（Bucket / 桶）
哈希表中存储元素的槽位。键经哈希函数计算索引后定位到对应桶。
- 关联：哈希表、哈希函数、哈希冲突
- 首次出现：6.1

### 哈希冲突（Hash Collision / 雜湊衝突）
两个不同的键经哈希函数映射到相同数组索引的现象。可通过链式地址或开放寻址解决。
- 关联：哈希函数、链式地址、开放寻址、负载因子
- 首次出现：6.1.3

### 负载因子（Load Factor / 負載因子）
哈希表中元素数量与桶数量的比值，反映哈希冲突的严重程度。当负载因子超过阈值时触发扩容。
- 关联：哈希冲突、哈希表、扩容
- 首次出现：6.1.3

### 链式地址（Separate Chaining / 鏈結位址）
将桶中的单个元素改为链表（或其他数据结构），所有冲突元素存储在同一链表中。链表过长会降低查询效率。
- 关联：哈希冲突、开放寻址、链表
- 首次出现：6.2.1

### 开放寻址（Open Addressing / 開放定址）
发生哈希冲突时，通过探测方法（线性探测、平方探测、多次哈希）在哈希表中寻找下一个可用空桶。
- 关联：哈希冲突、线性探测、平方探测、链式地址
- 首次出现：6.2.2

### 线性探测（Linear Probing / 線性探查）
发生冲突时，固定步长（通常为1）线性向后查找下一个空位。简单但容易产生聚集现象。
- 关联：开放寻址、平方探测、多次哈希
- 首次出现：6.2.2

### 哈希算法（Hash Algorithm）
广义的哈希函数设计方法，需满足确定性、高效性、均匀分布、抗碰撞等目标，如 MD5、SHA-1、SHA-2。
- 关联：哈希函数、哈希冲突
- 首次出现：6.3

## 五、树

### 二叉树（Binary Tree / 二元樹）
每个节点最多有两个子节点（左子节点和右子节点）的非线性树形数据结构，体现"一分为二"的分治逻辑。
- 关联：树节点、根节点、叶节点、二叉搜索树、子树
- 首次出现：7.1

### 根节点（Root Node / 根節點）
二叉树中唯一没有父节点的节点，位于树的顶端，是整个树的入口。
- 关联：叶节点、父节点、子树
- 首次出现：7.1.1

### 叶节点（Leaf Node / 葉節點）
没有子节点的节点，位于树的末端。
- 关联：根节点、度、高度
- 首次出现：7.1.1

### 边（Edge / 邊）
连接两个节点的引用的线，每个节点（除根节点外）向上有一条边连接父节点。
- 关联：节点、父节点、子节点
- 首次出现：7.1.1

### 度（Degree / 度）
一个节点的子节点数量。二叉树每个节点的度最大为 2。
- 关联：叶节点、二叉树、高度、深度
- 首次出现：7.1.1

### 高度 / 深度（Height / Depth）
高度：从叶节点到该节点经过的最多边数；深度：从根节点到该节点经过的边数。
- 关联：层、度、叶节点、根节点
- 首次出现：7.1.1

### 层（Level / 層）
从根节点开始按深度分组，根为第0层或第1层。层序遍历按层依次访问。
- 关联：高度、深度、层序遍历
- 首次出现：7.1.1

### 完美二叉树（Perfect Binary Tree / 完美二元樹）
所有层的节点都被完全填满的二叉树。第 k 层有 2ᵏ 个节点。
- 关联：完全二叉树、完满二叉树、平衡二叉树
- 首次出现：7.1.3

### 完全二叉树（Complete Binary Tree / 完全二元樹）
除最底层外各层填满，且最底层节点全部靠左排列的二叉树。适合用数组表示。
- 关联：完美二叉树、完满二叉树、堆、数组表示
- 首次出现：7.1.3

### 平衡二叉树（Balanced Binary Tree / 平衡二元樹）
任意节点的左子树和右子树高度差不超过 1 的二叉树（AVL 树是其严格实现）。
- 关联：AVL 树、平衡因子、红黑树
- 首次出现：7.1.3

### 二叉搜索树（Binary Search Tree / BST / 二元搜尋樹）
左子树所有节点值 < 根节点值 < 右子树所有节点值，查找/插入/删除均为 O(log n)，退化时为 O(n)。
- 关联：平衡二叉搜索树、AVL 树、中序遍历
- 首次出现：7.4

### AVL 树（AVL Tree）
严格平衡的二叉搜索树。每个节点的平衡因子（左子树高度 − 右子树高度）的绝对值 ≤ 1，通过旋转操作维持平衡。
- 关联：平衡二叉树、平衡因子、红黑树、旋转
- 首次出现：7.5

### 平衡因子（Balance Factor / 平衡因子）
AVL 树中节点的左子树高度减去右子树高度，必须保持在 {−1, 0, 1} 范围内。
- 关联：AVL 树、旋转、平衡二叉树
- 首次出现：7.5.1

### 红黑树（Red-Black Tree / 紅黑樹）
一种自平衡二叉搜索树，通过节点着色（红/黑）和旋转来保持近似平衡，平衡要求比 AVL 宽松但插入/删除更高效。
- 关联：AVL 树、平衡二叉树、二叉搜索树
- 首次出现：7.1.3（提及） / 7.5（深入见 AVL 对比）

### 层序遍历（Level-Order Traversal / 層序走訪）
逐层从上到下、每层从左到右遍历二叉树。属于广度优先搜索（BFS），通常用队列实现。
- 关联：广度优先搜索、前序遍历、中序遍历、后序遍历
- 首次出现：7.2.1

### 前序 / 中序 / 后序遍历（Pre-Order / In-Order / Post-Order Traversal）
三种深度优先搜索（DFS）遍历：前序遍历按"根→左→右"；中序遍历按"左→根→右"（BST 得有序结果）；后序遍历按"左→右→根"。
- 关联：深度优先搜索、二叉搜索树、递归
- 首次出现：7.2.2

### 广度优先搜索 / 深度优先搜索（BFS / DFS）
BFS：从起点"一圈一圈向外扩展"的遍历策略，用队列实现；DFS："先走到尽头再回溯"的遍历策略，用递归或栈实现。
- 关联：层序遍历、前序/中序/后序遍历、图遍历
- 首次出现：7.2（二叉树）/ 9.3（图）

## 六、堆

### 堆（Heap / 堆積）
一种特殊的完全二叉树。大顶堆中任意节点值 ≥ 其子节点值（根为最大）；小顶堆中任意节点值 ≤ 其子节点值（根为最小）。
- 关联：完全二叉树、优先队列、堆化、大顶堆、小顶堆
- 首次出现：8.1

### 大顶堆 / 小顶堆（Max Heap / Min Heap）
大顶堆：堆顶元素为整个堆的最大值；小顶堆：堆顶元素为整个堆的最小值。常用于实现优先队列。
- 关联：堆、优先队列、堆化
- 首次出现：8.1.1

### 优先队列（Priority Queue / 優先佇列）
出队顺序由元素优先级决定的队列，优先级高的先出。通常基于堆实现，入队/出队耗时 O(log n)。
- 关联：堆、大顶堆、小顶堆、队列
- 首次出现：8.1.3

### 堆化（Heapify / 堆積化）
维护堆性质的操作：从某节点开始，若其不满足堆条件则与子节点交换，递归向下修复。建堆可通过遍历堆化实现 O(n)。
- 关联：堆、大顶堆、小顶堆、入堆、出堆
- 首次出现：8.2.2

### Top‑k 问题
从 n 个元素中找出最大的（或最小的）k 个元素。使用小顶堆可高效解决，时间复杂度 O(n log k)。
- 关联：堆、优先队列、大顶堆
- 首次出现：8.3

## 七、图

### 图（Graph / 圖）
由一组顶点和连接顶点的边组成的非线性数据结构，表示多对多的网络关系。分为无向图、有向图、有权图等。
- 关联：顶点、边、邻接表、邻接矩阵、连通图
- 首次出现：9.1

### 顶点（Vertex / 頂點）
图中的基本节点，表示一个实体。与树的节点类似，但关系更自由。
- 关联：图、边、度
- 首次出现：9.1.1

### 无向图 / 有向图（Undirected / Directed Graph）
无向图：边无方向，A-B 可双向走；有向图：边有方向（箭头），只能单向走。
- 关联：图、邻接矩阵、邻接表
- 首次出现：9.1.1

### 连通图 / 非连通图（Connected / Disconnected Graph）
连通图：从任意顶点出发可达所有顶点；非连通图：存在不可达的顶点对。
- 关联：图、广度优先搜索、深度优先搜索
- 首次出现：9.1.1

### 有权图（Weighted Graph / 有權圖）
每条边带有权重的图，权重可以表示距离、成本、时间等。
- 关联：图、邻接矩阵、路径
- 首次出现：9.1.1

### 邻接（Adjacency / 鄰接）
两个顶点之间有边直接相连，则称这两点邻接。
- 关联：图、路径、顶点
- 首次出现：9.1.1

### 路径（Path / 路徑）
从一个顶点到另一个顶点经过的边的序列。
- 关联：图、邻接、广度优先搜索、深度优先搜索
- 首次出现：9.1.1

### 入度 / 出度（In-Degree / Out-Degree）
入度：指向该顶点的边数；出度：从该顶点出发的边数（仅适用于有向图）。
- 关联：图、有向图、度
- 首次出现：9.1.1

### 邻接矩阵（Adjacency Matrix / 鄰接矩陣）
用 n × n 矩阵表示图，matrix[i][j] 表示顶点 i 和 j 之间的边（无权图为 0/1，有权图为权重）。适合稠密图。
- 关联：邻接表、图、顶点
- 首次出现：9.1.2

### 邻接表（Adjacency List / 鄰接表）
用数组 + 链表表示图，每个顶点对应一个链表存储其邻接顶点。适合稀疏图。
- 关联：邻接矩阵、图、链表
- 首次出现：9.2.2

## 八、搜索算法

### 搜索算法（Searching Algorithm / 搜尋演算法）
在数据结构中查找目标元素的算法。包括暴力搜索、二分查找、哈希查找等。
- 关联：二分查找、广度优先搜索、深度优先搜索、哈希查找
- 首次出现：10.5

### 二分查找（Binary Search / 二分搜尋）
基于有序数组的搜索算法，每轮将搜索区间缩小一半，时间复杂度 O(log n)。要求数据有序且支持随机访问。
- 关联：搜索算法、对数阶、分治策略
- 首次出现：10.1

### 暴力搜索（Brute-Force Search）
遍历数据结构中每个元素直到找到目标的朴素方法。线性搜索 O(n) 适用于数组/链表，BFS/DFS 适用于图/树。
- 关联：线性查找、BFS、DFS、搜索算法
- 首次出现：10.5.1

### 自适应搜索（Adaptive Search）
利用数据结构的特性（如有序性、哈希映射）加速搜索的高效方法，如二分查找 O(log n)、哈希查找 O(1)。
- 关联：二分查找、哈希查找、搜索算法
- 首次出现：10.5.2

## 九、排序算法

### 排序算法（Sorting Algorithm / 排序演算法）
将一组数据按指定顺序（升序/降序）重新排列的算法。评价维度包括时间复杂度、空间复杂度、稳定性。
- 关联：冒泡排序、快速排序、归并排序、选择排序、插入排序
- 首次出现：11.1

### 选择排序（Selection Sort / 選擇排序）
每轮从未排序区间选出最小元素，放到已排序区间末尾。时间复杂度 O(n²)，非稳定排序。
- 关联：排序算法、冒泡排序、插入排序
- 首次出现：11.2

### 冒泡排序（Bubble Sort / 泡沫排序）
相邻元素两两比较，将较大的向右"冒泡"。每轮确定一个最大元素位置。时间复杂度 O(n²)，稳定排序。
- 关联：排序算法、选择排序、插入排序
- 首次出现：11.3

### 插入排序（Insertion Sort / 插入排序）
将未排序区间元素依次插入已排序区间正确位置，类似理牌。时间复杂度 O(n²)，稳定，小规模数据高效。
- 关联：排序算法、选择排序、冒泡排序
- 首次出现：11.4

### 快速排序（Quick Sort / 快速排序）
选取基准数 pivot，将数组分为小于和大于 pivot 的两部分，递归排序。时间复杂度平均 O(n log n)，最差 O(n²)。
- 关联：归并排序、分治策略、基准数、递归
- 首次出现：11.5

### 归并排序（Merge Sort / 合併排序）
递归地将数组二分至单个元素，再合并已排序子数组。时间复杂度 O(n log n)，稳定，需要 O(n) 辅助空间。
- 关联：快速排序、堆排序、分治策略
- 首次出现：11.6

### 堆排序（Heap Sort / 堆積排序）
基于堆数据结构的选择排序：建堆 O(n)，依次取堆顶（最大/最小）出堆 O(n log n)。不稳定，原地排序。
- 关联：堆、选择排序、归并排序
- 首次出现：11.7

### 桶排序（Bucket Sort / 桶排序）
将元素分到多个桶内，每个桶内排序后合并。时间复杂度 O(n + k)，适合数据均匀分布。
- 关联：计数排序、基数排序、排序算法
- 首次出现：11.8

### 计数排序（Counting Sort / 計數排序）
通过统计每个值出现的次数实现排序，时间复杂度 O(n + m)，m 为值域大小。适用于整数且值域不大的场景。
- 关联：桶排序、基数排序
- 首次出现：11.9

### 基数排序（Radix Sort / 基數排序）
按数位（个位、十位、百位…）依次进行稳定排序，从低位到高位。时间复杂度 O(d(n + k))，d 为位数。
- 关联：计数排序、桶排序、排序算法
- 首次出现：11.10

## 十、算法范式

### 分治算法（Divide and Conquer / 分治）
将原问题分解为多个规模更小的子问题，递归求解后合并结果。典型应用：归并排序、二分查找、汉诺塔、构建二叉树。
- 关联：归并排序、二分查找、递归、动态规划、汉诺塔
- 首次出现：12.1

### 汉诺塔问题（Tower of Hanoi / 河內塔問題）
经典的递归/分治问题：将 n 个大小不同的圆盘从一根柱子移动到另一根，每次移动一个盘且大盘不能压小盘。
- 关联：分治算法、递归、递归树
- 首次出现：12.4

### 回溯算法（Backtracking Algorithm / 回溯演算法）
通过深度优先搜索遍历解空间树，遇到不满足约束的状态则回退（撤销选择）尝试其他分支。本质是穷举法+剪枝优化。
- 关联：深度优先搜索、剪枝、约束、动态规划、全排列
- 首次出现：13.1

### 约束（Constraint / 約束）
回溯问题中限制可行解的条件，如 n 皇后的攻击规则、子集和的目标值。约束用于剪枝。
- 关联：回溯算法、剪枝、状态
- 首次出现：13.1.2

### 剪枝（Pruning / 剪枝）
在回溯搜索中，若当前分支不可能产生合法解，则提前终止该分支的搜索，大幅减少搜索空间。
- 关联：回溯算法、约束、状态
- 首次出现：13.1.2

### 解（Solution / 解）
满足问题所有约束条件的一个完整结果，如全排列问题中的一种排列。
- 关联：回溯算法、状态、约束
- 首次出现：13.1.4

### 状态（State / 狀態）
回溯问题中当前搜索阶段的信息快照，包括已做选择和剩余可选项。
- 关联：回溯算法、动态规划、状态转移方程
- 首次出现：13.1.4

### 全排列问题（Permutations Problem / 全排列問題）
在回溯问题中寻找给定集合所有可能的排列顺序。有重复元素时需去重（约束相等元素的相对顺序）。
- 关联：回溯算法、剪枝、子集和问题、n 皇后问题
- 首次出现：13.2

### 子集和问题（Subset-Sum Problem / 子集合問題）
从给定集合中找出和为目标值的所有子集。需处理重复元素导致的重复子集。
- 关联：回溯算法、剪枝、全排列问题
- 首次出现：13.3

### n 皇后问题（n-Queens Problem / n 皇后問題）
在 n × n 棋盘上放置 n 个皇后，满足互不攻击（不同行、不同列、不同对角线）。
- 关联：回溯算法、剪枝、约束、全排列问题
- 首次出现：13.4

### 动态规划（Dynamic Programming / 動態規劃）
将复杂问题分解为重叠子问题，通过存储子问题解避免重复计算。从底至顶递推求解。要求具有最优子结构和无后效性。
- 关联：回溯算法、记忆化搜索、最优子结构、状态转移方程、分治
- 首次出现：14.1

### 最优子结构（Optimal Substructure / 最優子結構）
原问题的最优解可以从子问题的最优解构建而来。动态规划适用的必要条件之一。
- 关联：动态规划、无后效性、重叠子问题、贪心算法
- 首次出现：14.2.1

### 无后效性（No Aftereffect / 無後效性）
给定某个状态，其未来发展只与该状态本身有关，与如何到达该状态的路径（历史）无关。
- 关联：动态规划、最优子结构、状态
- 首次出现：14.2.2

### 重叠子问题（Overlapping Subproblems / 重疊子問題）
原问题分解后的子问题存在大量重复。动态规划通过存储子问题解避免重复计算。
- 关联：动态规划、记忆化搜索、分治
- 首次出现：14.1.2

### 状态转移方程（State-Transition Equation / 狀態轉移方程）
描述当前状态与子问题状态之间递推关系的数学公式，是动态规划求解的核心。
- 关联：动态规划、最优子结构、状态
- 首次出现：14.1.3

### 记忆化搜索（Memoization / 記憶化搜索）
从顶至底的递归求解方式，将子问题结果缓存以避免重复计算。是动态规划的一种实现形式。
- 关联：动态规划、递归、重叠子问题
- 首次出现：14.1.2

### 0‑1 背包问题（0-1 Knapsack Problem / 背包問題）
在容量有限的背包中选取物品，每件物品要么不选（0）要么选一次（1），求最大价值。经典动态规划问题。
- 关联：动态规划、状态转移方程、完全背包
- 首次出现：14.4

### 完全背包问题（Unbounded Knapsack Problem）
0‑1 背包的变种：每种物品可选无限次。状态转移方程与 0‑1 不同（选入后仍可在同物品上继续选择）。
- 关联：0‑1 背包问题、动态规划、零钱兑换
- 首次出现：14.5.1

### 编辑距离问题（Edit Distance Problem / 編輯距離問題）
计算将一个字符串转换成另一个字符串所需的最少编辑操作（插入/删除/替换）次数。经典动态规划问题。
- 关联：动态规划、状态转移方程、背包问题
- 首次出现：14.6

### 贪心算法（Greedy Algorithm / 貪婪演算法）
在每步决策中选择当前局部最优解，期望最终得到全局最优解。适用于具有贪心选择性质的问题。实现简单、效率高。
- 关联：动态规划、最优子结构、背包问题
- 首次出现：15.1

### 贪心选择性质（Greedy Choice Property）
当前局部最优选择能导向全局最优解。贪心算法适用的必要前提，通常需要数学证明。
- 关联：贪心算法、最优子结构、动态规划
- 首次出现：15.1.2

## 十一、编程基础

### 循环（Loop / 迴圈）
重复执行一段代码的控制结构。Dart 中支持 for 循环、while 循环、for-in 遍历等。是迭代的基本实现方式。
- 关联：迭代、递归、嵌套循环
- 首次出现：2.2.1

### 迭代（Iteration / 迭代）
通过循环结构反复执行代码来解决问题的过程。显式控制循环变量和终止条件，不涉及函数自调用。
- 关联：循环、递归、for 循环、while 循环
- 首次出现：2.2

### 递归（Recursion / 遞迴）
函数调用自身来解决问题的方法。每层递归将问题缩小一个规模，直到触达终止条件（base case）后逐层返回。
- 关联：迭代、递推、基线条件、调用栈、尾递归
- 首次出现：2.2

### 尾递归（Tail Recursion / 尾遞迴）
递归调用发生在函数最后一条语句的递归形式。编译器可优化为迭代以节省调用栈空间。
- 关联：递归、调用栈、迭代
- 首次出现：2.2.2

### 调用栈（Call Stack）
程序在执行函数调用时维护的栈结构，记录每次函数调用的返回地址和局部变量。递归过深可能导致栈溢出。
- 关联：递归、尾递归、栈
- 首次出现：2.2.2

### 递归树（Recursion Tree / 遞迴樹）
以树状结构展示递归分解过程的可视化图形。根节点为原问题，子节点为子问题，叶节点为基线条件。
- 关联：递归、分治、动态规划、回溯
- 首次出现：2.2.2

### 迭代与递归的关系
迭代和递归是两种基本算法实现方式：迭代通过循环结构显式控制，递归通过函数自调用隐式分解。二者可互相转化。递推（迭代）是从底向上，递归是从顶向下。
- 关联：迭代、递归、递推、调用栈
- 首次出现：2.2.3

## 十二、计算机底层

### 逻辑结构 / 物理结构（Logical / Physical Structure）
逻辑结构：数据元素之间的抽象逻辑关系（线性、树形、网状）；物理结构：数据在计算机内存中的实际存储方式（连续 or 分散）。
- 关联：数组、链表、树、图、内存
- 首次出现：3.1

### 内存（RAM / 記憶體）
计算机运行时存储程序和数据的高速读写设备，以字节为单位编址。断电后数据丢失，与硬盘互补。
- 关联：硬盘、缓存、内存地址、数组
- 首次出现：4.4.1

### 缓存（Cache / 快取）
CPU 与内存之间的高速小容量存储器。利用空间/时间局部性原理预取数据，高缓存命中率可大幅提升性能。
- 关联：内存、缓存命中率、缓存未命中、数组
- 首次出现：4.4.1

### 缓存命中 / 未命中（Cache Hit / Miss）
缓存命中：所需数据已在缓存中，直接读取（快）；缓存未命中：数据不在缓存中，需从下层存储读取（慢）。
- 关联：缓存、内存、数组、链表
- 首次出现：4.4.3

### 原码 / 反码 / 补码（Sign-Magnitude / 1's Complement / 2's Complement）
三种计算机编码整数的方法。原码：最高位为符号位；反码：负数除符号位外每位取反；补码：反码 + 1。现代计算机统一用补码存储整数。
- 关联：数字编码、浮点数编码、整数
- 首次出现：3.3.1

### 浮点数编码（Floating-Point Encoding）
按 IEEE 754 标准由符号位(1位)、指数位(8位)、尾数位(23位)构成。因指数位的存在，浮点数取值范围远大于同位数整数。
- 关联：原码/反码/补码、double、float
- 首次出现：3.3.2

### ASCII / GBK / Unicode / UTF‑8
ASCII：7位英文字符集（127字符）；GBK：中文字符集（两字节编码）；Unicode：统一字符集标准；UTF‑8：可变长 Unicode 编码，最流行。

- 首次出现：3.4

### Dart 中的 List 与数组
Dart 的 List 类基于动态数组实现，支持 len、[]、add、remove、sort 等方法。底层为连续内存 + 自动扩容机制。
- 关联：数组、动态数组、链表
- 首次出现：4.1 / 4.3

### Dart 中的链表实现
Dart 无内置链表类，需自定义 ListNode 节点类，包含 val 和 next 两属性，通过引用串联节点。
- 关联：链表、链表节点、Dart 类
- 首次出现：4.2.1

## 十三、重要概念关系

### 分治 vs 回溯 vs 动态规划
三者都涉及问题分解，但性质不同：分治的子问题相互独立（如归并排序）；回溯是穷举搜索+剪枝（子问题可能重叠，但不存储解）；动态规划的子问题重叠（必须存储子问题解，避免重复计算）。
- 关联：分治算法、回溯、动态规划、重叠子问题
- 首次出现：14.1（对比阐述）

### 动态规划 vs 贪心算法
动态规划考虑所有可能选择的最优结果（全局最优）；贪心算法每步仅做局部最优选择。贪心效率更高但适用面更窄，必须满足贪心选择性质；动态规划更通用但复杂度更高。
- 关联：动态规划、贪心算法、最优子结构
- 首次出现：15.1.2（对比阐述）

### BFS vs DFS
BFS 逐层扩展、用队列实现、适合求最短路径；DFS 深入到底再回溯、用递归/栈实现、适合穷举/回溯。二者时间复杂度相同 O(V + E)，空间复杂度不同。
- 关联：广度优先搜索、深度优先搜索、队列、栈、回溯
- 首次出现：9.3（对比阐述）

### 数组 vs 链表
数组连续存储、O(1) 随机访问、O(n) 插入删除、缓存友好；链表分散存储、O(n) 访问、O(1) 插入删除、内存开销大（需存储指针）。选择取决于访问/修改模式。
- 关联：数组、链表、List、动态数组
- 首次出现：4.2.2

### 栈 vs 队列
栈是 LIFO（后进先出），仅栈顶可操作；队列是 FIFO（先进先出），队尾入队、队首出队。双向队列兼具二者功能。
- 关联：栈、队列、双向队列
- 首次出现：5.1 / 5.2

### 哈希表 vs 二叉搜索树
哈希表查询/插入/删除均为 O(1)（平均），但不支持有序操作；BST O(log n) 且支持范围查询、有序遍历。哈希表以空间换时间。
- 关联：哈希表、二叉搜索树、AVL 树
- 首次出现：7.4.2（对比阐述）

### 稳定排序 vs 非稳定排序
稳定排序：相等元素的相对顺序在排序前后保持不变（冒泡、插入、归并）；非稳定排序：相等元素相对顺序可能改变（选择、快速、堆）。
- 关联：冒泡排序、插入排序、归并排序、快速排序
- 首次出现：11.1.1

### 原地排序 vs 非原地排序
原地排序：不需要额外辅助空间或仅需 O(1) 额外空间（冒泡、插入、选择、快速、堆）；非原地排序：需要 O(n) 辅助空间（归并、桶、计数）。
- 关联：空间复杂度、归并排序、快速排序
- 首次出现：11.1.1

### 时间换空间 vs 空间换时间
算法优化的两种基本策略。如暴力搜索以时间换空间，哈希查找以空间换时间。需根据实际硬件资源权衡。
- 关联：时间复杂度、空间复杂度、哈希优化、缓存
- 首次出现：10.4

### 递归与调用栈的关系
每次递归调用在调用栈中压入一个栈帧（保存参数/局部变量/返回地址），递归返回时弹出。过深递归可导致栈溢出（stack overflow）。
- 关联：递归、调用栈、尾递归、栈溢出
- 首次出现：2.2.2

### 堆与优先队列的关系
优先队列是一种抽象数据类型（ADT），定义出队优先级规则；堆是一种具体数据结构，是优先队列的最高效实现方式。
- 关联：堆、优先队列、队列、大顶堆
- 首次出现：8.1.3
