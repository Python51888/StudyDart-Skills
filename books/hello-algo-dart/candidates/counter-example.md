## 复杂度认知与分析方法陷阱

### 1. 时间复杂度相同实际性能可能差数十倍

| 字段 | 内容 |
|------|------|
| **书中位置** | 第2章 复杂度分析 / 2.3 时间复杂度 |
| **关联知识点** | 时间复杂度、大 O 记号、常数因子 |
| **错误描述** | 时间复杂度忽略了常数因子、低阶项和运行环境差异。两个同为 O(n) 的算法，一个可能执行 2n 次操作，另一个执行 100n 次操作，实际运行时间相差 50 倍。时间复杂度并非精确的时间度量，它只是增长趋势的估计。 |
| **后果** | 盲目选择理论复杂度相同的算法而不做实际测试，可能导致性能远低于预期。当 n 较小时，常数因子和低阶项主导实际性能。 |
| **正确做法** | （1）先用复杂度分析缩小候选范围；（2）必须进行实际场景的基准测试；（3）关注嵌套循环内层的实际操作次数。 |

### 2. 递归函数调用开销远大于迭代

| 字段 | 内容 |
|------|------|
| **书中位置** | 第2章 复杂度分析 / 2.2 迭代与递归 |
| **关联知识点** | 迭代、递归、函数调用机制 |
| **错误描述** | 每次递归调用需要保存和恢复上下文（参数压栈、局部变量、返回地址），函数调用的栈帧分配和释放开销远大于循环变量的简单更新。对于简单任务如求和或阶乘，递归版本常数因子是迭代的数倍。 |
| **后果** | 递归实现的常数时间远大于迭代，在性能敏感场景和实时系统中不可接受。 |
| **正确做法** | （1）简单重复任务优先用迭代（for/while）；（2）仅在问题天然递归（树遍历、分治、回溯）时才用递归；（3）性能关键路径避免不必要的函数调用；（4）尾递归可部分缓解但不可依赖。 |

## 递归陷阱

### 3. 递归深度过大导致栈溢出

| 字段 | 内容 |
|------|------|
| **书中位置** | 第2章 复杂度分析 / 2.2 迭代与递归 |
| **关联知识点** | 调用栈、栈帧空间、递归深度 |
| **错误描述** | 递归处理大规模数据时深度与输入规模成正比。如对长度为 n 的链表递归反转、退化树递归遍历、快速排序最坏基准选取，递归深度均可达 n。当超过系统栈限制时发生 StackOverflow。 |
| **后果** | 程序直接崩溃。即使不崩溃，每层递归的上下文保存消耗 O(n) 栈空间，空间复杂度远高于迭代。 |
| **正确做法** | （1）改写为显式栈迭代；（2）尾递归优化但不可依赖；（3）快速排序中每次递归短子数组将深度优化到 O(log n)；（4）设置递归深度限制并提前终止。 |

### 4. 尾递归优化不被所有平台支持仍可能栈溢出

| 字段 | 内容 |
|------|------|
| **书中位置** | 第2章 复杂度分析 / 2.2 迭代与递归 |
| **关联知识点** | 尾递归、编译器优化、Dart 运行环境 |
| **错误描述** | 书中明确指出：许多编译器或解释器并不支持尾递归优化。即使函数是尾递归形式，仍然可能会遇到栈溢出问题。Dart 的尾递归优化取决于运行平台（原生 vs Web/JS），支持不稳定。 |
| **后果** | 代码看起来是优化版，实际仍消耗 O(n) 栈空间，大规模数据下照样栈溢出。程序员误以为已优化而放松警惕。 |
| **正确做法** | （1）不依赖尾递归优化来保证效率；（2）不确定时直接改写为迭代；（3）显式测试递归深度上限；（4）习惯用循环替代递归处理线性结构。 |

### 5. 递归体内分配数组导致 O(n²) 栈空间

| 字段 | 内容 |
|------|------|
| **书中位置** | 第2章 复杂度分析 / 2.4 空间复杂度 |
| **关联知识点** | 递归空间复杂度分析、栈帧空间累积 |
| **错误描述** | 在递归函数体内每层初始化数据（如每帧中 List.filled(n - depth, 0)），导致每层递归都分配新数组。n 层递归同时存在的栈帧总空间为 O(1+2+...+n) = O(n²)，而非直觉以为的 O(n)。 |
| **后果** | 递归空间复杂度从 O(n) 爆炸到 O(n²)，极易超出内存限制，分析错误导致对算法适用规模产生严重误判。 |
| **正确做法** | （1）在递归外一次性创建数组并传引用复用；（2）分析所有栈帧的内存分配总和；（3）计算同时存在的所有栈帧空间作为递归空间复杂度。 |

### 6. 树递归遍历最坏退化时栈深度为 n

| 字段 | 内容 |
|------|------|
| **书中位置** | 第7章 树 / 7.2 二叉树遍历；第12章 分治 / 12.3 构建二叉树问题 |
| **关联知识点** | 二叉树遍历、递归深度、退化树 |
| **错误描述** | 前中后序遍历使用递归时，递归深度等于树的高度。二叉树退化为链表时（完全右斜或左斜），高度 = n。n=10^5 时直接栈溢出。最坏情况还需 O(n) 空间存储哈希表（如构建二叉树时记录 inorder 映射）。 |
| **后果** | 程序崩溃。即使显式栈的迭代版本最坏情况也需 O(n) 辅助空间。 |
| **正确做法** | （1）使用莫里斯遍历 O(1) 空间；（2）显式栈模拟递归避免系统栈限制；（3）保持树平衡确保高度 O(log n)。 |

## 数据结构误用

### 7. 在数组头部或中间频繁插入删除

| 字段 | 内容 |
|------|------|
| **书中位置** | 第4章 数组与链表 / 4.1 数组；第5章 栈与队列 / 5.2 队列 |
| **关联知识点** | 数组、链表、队列、数据结构选择 |
| **错误描述** | 在数组非末尾位置插入或删除元素时，需要将后续所有元素移动一位 O(n)。如直接用数组实现队列头部出队，每次 O(n)。频繁此类操作累计 O(n²)。 |
| **后果** | 每次操作 O(n)，任务调度和消息队列等频繁增删场景性能不可接受。 |
| **正确做法** | （1）用 front 指针加循环数组实现 O(1) 出队；（2）用链表 O(1)；（3）平衡树 O(log n)；（4）顺序不重要时末尾元素替代删除位置 O(1)。 |

### 8. 无序数组做频繁查找导致算法退化

| 字段 | 内容 |
|------|------|
| **书中位置** | 第6章 哈希表 / 6.1 哈希表；第10章 搜索 / 10.4 哈希优化策略 |
| **关联知识点** | 线性查找、哈希查找、Two Sum 问题 |
| **错误描述** | 需要频繁查找元素时用无序数组需 O(n) 线性遍历。典型如 Two Sum 问题中对每个元素遍历整个数组找目标值，时间复杂度 O(n²)。 |
| **后果** | n=10^5 时约 50 亿次比较，远超时间限制。算法从可能的 O(n) 退化到 O(n²)。 |
| **正确做法** | （1）频繁查找立即改用哈希表 O(1)；（2）需有序遍历用平衡树 O(log n)；（3）Two Sum 用哈希集合存已遍历元素，一趟 O(n)；（4）数据量很小时数组常数因子可能更优。 |

### 9. 链表节点内存开销远超数组元素

| 字段 | 内容 |
|------|------|
| **书中位置** | 第4章 数组与链表 / 4.2 链表；第4章 / 4.5 小结 |
| **关联知识点** | 链表、节点指针、内存布局、缓存局部性 |
| **错误描述** | 链表每个节点需额外存储指针（单链表 1 个引用，双链表 2 个引用）。加上 Dart 对象头开销，链表节点实际内存占用是数组元素的 3 到 5 倍。节点分散在堆中导致 CPU 缓存命中率低，顺序遍历也慢于数组数倍。 |
| **后果** | 相同数据量下链表内存远超数组。缓存缺失导致遍历慢，"链表更省空间"的直觉在多数情况下是错的。 |
| **正确做法** | （1）数据量固定加随机访问用数组；（2）频繁增删且顺序访问用链表；（3）权衡内存和访问模式；（4）现代 CPU 架构下数组因缓存优势通常比链表更快。 |

### 10. 数组预分配过多导致内存浪费

| 字段 | 内容 |
|------|------|
| **书中位置** | 第4章 数组与链表 / 4.1 数组；第5章 栈与队列 / 5.1 栈 |
| **关联知识点** | 数组容量、内存分配、空间利用率 |
| **错误描述** | 预分配过大的数组（如预估 1000 个但只用 5 个），大量空间被浪费。栈的数组实现中如果初始化较长数组而只用前面部分，丢失的末尾元素空间被白白占用。 |
| **后果** | 空间利用率极低，大对象数组场景内存浪费可能达 GB 级。 |
| **正确做法** | （1）使用动态数组自动扩容；（2）无法预估时用链表；（3）明确知道上限时才预分配；（4）用 List.filled 精确控制容量。 |

### 11. 邻接矩阵存储稀疏图浪费 O(V²) 空间

| 字段 | 内容 |
|------|------|
| **书中位置** | 第9章 图 / 9.2 图的基础操作 |
| **关联知识点** | 邻接矩阵、邻接表、稀疏图、稠密图 |
| **错误描述** | 邻接矩阵使用 O(|V|²) 空间存储图。对于稀疏图（|E| << |V|²），绝大部分矩阵元素为 0，空间利用率极低。遍历邻接矩阵需检查每对顶点 O(|V|²) vs 邻接表只需遍历出边 O(|V|+|E|)。 |
| **后果** | |V|=10^6 稀疏图：邻接矩阵约 1TB，邻接表约 100MB。遍历效率也相差悬殊。 |
| **正确做法** | 稀疏图用邻接表（空间 O(|V|+|E|)）；稠密图（|E|接近|V|²）用邻接矩阵（常数小且 O(1) 边查询）。口诀：邻接矩阵以空间换时间，邻接表以时间换空间。 |

### 12. 二叉树数组表示在非完全二叉树下空间浪费

| 字段 | 内容 |
|------|------|
| **书中位置** | 第7章 树 / 7.3 二叉树数组表示 |
| **关联知识点** | 完全二叉树、数组存储、空间复杂度 |
| **错误描述** | 用数组表示二叉树时（索引 i 的左子 2i+1，右子 2i+2），非完全二叉树特别是右斜树会产生大量空位。最坏情况每层仅一个右子节点的链表形态，需 2^n 大小数组存 n 个节点。 |
| **后果** | n 个节点的退化树可能需要 O(2^n) 数组空间，完全不可用。 |
| **正确做法** | （1）二叉树数组表示仅适用于完全二叉树或堆；（2）一般二叉树使用链式存储（节点加左右指针）；（3）先判断树的形态再选存储方式。 |

## 哈希冲突与哈希表陷阱

### 13. 哈希冲突不可避免严重时退化到 O(n)

| 字段 | 内容 |
|------|------|
| **书中位置** | 第6章 哈希表 / 6.2 哈希冲突 |
| **关联知识点** | 哈希函数、鸽巢原理、负载因子、链地址法 |
| **错误描述** | 哈希函数输入空间远大于输出空间，鸽巢原理保证冲突必然发生。负载因子高加哈希函数质量差时，大量键映射到同一桶。链地址法的链表退化为 O(n) 查找，开放寻址探测次数剧增。最差情况下所有键值对存储在同一个桶中。 |
| **后果** | 哈希表 O(1) 退化到 O(n)，所有依赖哈希表的算法整体坍塌。安全场景可被哈希洪水攻击导致拒绝服务。 |
| **正确做法** | （1）使用分布均匀的哈希函数；（2）负载因子小于 0.75；（3）及时触发扩容 rehash；（4）安全场景使用加密哈希防 Hash DoS；（5）链地址法严重时可改为平衡树。 |

### 14. 懒删除 TOMBSTONE 加速哈希表性能退化

|------|------|
| **书中位置** | 第6章 哈希表 / 6.2 哈希冲突 |
| **关联知识点** | 开放寻址、懒删除、TOMBSTONE、探测链 |
| **错误描述** | 开放寻址中删除不真正移除（会切断探测链导致被挤到后面的元素无法找到），而是标记为 TOMBSTONE。随增删交替墓碑积累，有效负载因子虚高，查找需越过大量墓碑。 |

## 排序陷阱

### 22. 快速排序在有序或逆序输入下退化为 O(n²)

| 字段 | 内容 |
|------|------|
| **书中位置** | 第11章 排序 / 11.5 快速排序 |
| **关联知识点** | 快速排序、哨兵划分、基准数选取、递归深度 |
| **错误描述** | 数组完全有序或逆序时若基准数总是选取最左或最右元素，每次划分仅排除一个元素，递归深度达 n，总时间 O(n²)。书中明确假设输入数组完全倒序，选择最左端元素作为基准数，左子数组长度为 n-1 右子数组长度为 0。 |
| **后果** | 时间复杂度从期望 O(n log n) 退化到 O(n²)，递归深度 n 可能栈溢出。在数据已基本有序的场景反而最差。 |

### 23. 快速排序在元素全相等时也退化为 O(n²)

| 字段 | 内容 |
|------|------|
| **书中位置** | 第11章 排序 / 11.11 小结（Q&A） |
| **关联知识点** | 快速排序、相等元素处理、三路快排 |
| **错误描述** | 数组中所有元素都相等时标准哨兵划分（小于基准放左大于等于放右）可能将所有元素分到一边，导致退化为 O(n²)。 |
| **后果** | 元素相等场景在实际数据中不罕见（如按类别排序），期望 O(n log n) 退化到 O(n²)。 |

### 24. 不稳定排序破坏多关键字排序结果

## 二分查找陷阱

### 30. 二分查找边界条件陷阱双闭 vs 左闭右开

| 字段 | 内容 |
|------|------|
| **书中位置** | 第10章 搜索 / 10.1 二分查找 |
| **关联知识点** | 二分查找、循环不变量、区间定义、边界条件 |
| **错误描述** | 二分查找有两种区间表示：双闭区间 [i, j] 配 while(i<=j)，左闭右开 [i, j) 配 while(i<j)。混用区间定义和循环条件会导致漏查或死循环。双闭区间中左右边界操作对称更容易避免出错。 |
| **后果** | 漏查目标元素返回错误结果；或 i=j 时 while 死循环（区间不缩小但条件恒真）；搜索插入点时数组越界。 |
| **正确做法** | （1）明确选择一种区间定义全程一致；（2）双闭：while(i<=j)+m-1+m+1；（3）左闭右开：while(i<j)+m+m+1；（4）不混用；（5）优先用双闭区间更不易出错。 |

### 31. 二分查找 mid 计算中的整数溢出

| 字段 | 内容 |
|------|------|
| **书中位置** | 第10章 搜索 / 10.1 二分查找 |
| **关联知识点** | 整数溢出、二分查找、mid 计算公式 |
| **错误描述** | 书中明确指出 mid = (i+j) ~/ 2 中 i+j 可能超出 int 取值范围导致溢出为负数。i 和 j 都是 int 类型 i+j 可能超 int 最大值溢出后数组索引越界。 |
| **后果** | 溢出导致负数索引引发数组越界异常。大数组中尤其危险（数组长度接近 int 上限时）。 |
| **正确做法** | 使用 mid = i + (j - i) ~/ 2。此公式在 i 和 j 为正时不溢出且数学等价。书中所有二分查找实现都使用此安全写法。 |

### 32. 二分查找仅适用有序数组不适用高频增删

| 字段 | 内容 |

| **关联知识点** | 二分查找、有序性依赖、数据结构选择、哈希查找 |
| **错误描述** | 二分查找有两个前提：（1）数据必须有序；（2）必须支持 O(1) 随机访问（仅适用数组）。不适用链表（无 O(1) 随机访问）、无序数据、高频增删场景（每次增删需维护有序数组 O(n) 开销过大）。 |
| **后果** | 不满足前提条件时二分查找完全不可用或得不偿失。维护有序数组代价 O(n) 远超二分查找节省的 O(log n) vs O(n) 查找差。 |
| **正确做法** | （1）低频查找加高频增删用哈希表 O(1) 查找加增删；（2）低频增删加高频查找用有序数组加二分；（3）既需频繁增删又需有序用平衡树 O(log n)。 |

## 动态规划与记忆化

### 33. 忽略重叠子问题朴素递归导致指数爆炸

| 字段 | 内容 |
|------|------|
| **书中位置** | 第14章 动态规划 / 14.1 初探动态规划；14.2 动态规划问题特性 |
| **关联知识点** | 重叠子问题、记忆化搜索、动态规划、斐波那契数列 |
| **错误描述** | 对具有重叠子问题特性的问题（斐波那契、爬楼梯、网格最短路径、背包问题），朴素递归无缓存导致大量重复计算。斐波那契递归树中 fib(k) 被计算 exp(n-k) 次，总复杂度约 O(1.618^n)。"暴力搜索生成的递归树存在大量重叠子问题"。 |
| **后果** | 时间复杂度从 O(n)（DP）退化到 O(2^n)。n=50 时计算量达万亿级程序永远无法完成。 |
| **正确做法** | （1）先问"这个问题有重叠子问题吗"有则用记忆化或 DP；（2）记忆化搜索自顶向下加备忘录缓存；（3）动态规划自底向上建 DP 表；（4）按"暴力搜索到记忆化搜索到动态规划"顺序逐步演进。 |

### 34. DP 空间优化中的倒序正序遍历错误

| 字段 | 内容 |
|------|------|
| **书中位置** | 第14章 动态规划 / 14.3 动态规划解题思路；14.4 0-1 背包问题 |
| **关联知识点** | 状态压缩、倒序遍历、无后效性、0-1 背包 vs 完全背包 |
| **错误描述** | 将二维 DP 压缩为一维时 0-1 背包必须倒序遍历（从大到小），完全背包必须正序遍历。若 0-1 背包正序遍历会导致同一物品被多次选取（读到本行刚更新的左侧状态）。书中强调"需要倒序遍历列表避免左上方状态被覆盖"。 |
| **后果** | 0-1 背包变成完全背包结果完全错误。正倒序错误是 DP 空间优化中最常见的 bug。 |
| **正确做法** | （1）0-1 背包倒序从 cap 到 wgt[i] 防止重复选；（2）完全背包正序从 wgt[i] 到 cap 允许重复选；（3）画 DP 表理解状态依赖方向再决定遍历顺序；（4）第三步确定边界条件和状态转移顺序是 DP 的核心。 |

### 35. 回溯搜索的组合爆炸

| 字段 | 内容 |
|------|------|
| **书中位置** | 第13章 回溯 / 13.1 回溯算法；13.5 小结 |
| **关联知识点** | 回溯、剪枝、组合爆炸、指数级复杂度 |
| **错误描述** | 回溯本质是解空间的枚举（带剪枝的暴力搜索），复杂度常为 O(k^n) 或 O(n!)。N 皇后 O(n!)、旅行商 O(n!)、全排列 O(n!)、子集 O(2^n)。不剪枝时必然超时。 |
| **后果** | n 从 10 增到 15 运行时间增长数万倍实际不可用。无剪枝的回溯与暴力搜索无异。 |
| **正确做法** | （1）必须配合剪枝（约束剪枝加限界剪枝）减小搜索空间；（2）优先检查有无多项式解如 DP；（3）使用启发式搜索如 A*；（4）评估实际搜索空间大小是否可接受；（5）让剪枝尽量发生在搜索树的浅层。 |

### 36. 缺少 visited 数组导致图搜索重复访问

| 字段 | 内容 |
|------|------|
| **书中位置** | 第9章 图 / 9.3 图的遍历；第13章 回溯 / 13.1 回溯算法 |
| **关联知识点** | DFS、BFS、visited 集合、图遍历 |
| **错误描述** | 图 DFS/BFS 中没有 visited 集合记录已访问顶点，会在环路中无限循环。回溯中缺少 visited 或选择列表会导致同一元素被重复选择（如在排列中重复选同一数字）。 |
| **后果** | 图搜索在环中无限循环堆溢出。回溯生成大量无效重复解（如重复子集、重复排列）导致搜索空间爆炸。 |
| **正确做法** | （1）图搜索必须维护 visited 集合；（2）回溯中通过 start 索引或 used 数组避免重复选择同一元素；（3）子集问题从 start 开始遍历避免生成重复子集；（4）N 皇后中用 cols/diags 数组剪枝。 |

## 贪心算法陷阱

### 37. 贪心策略得不到全局最优解零钱兑换经典反例

| 字段 | 内容 |
|------|------|
| **书中位置** | 第15章 贪心 / 15.1 贪心算法 |
| **关联知识点** | 贪心算法、最优子结构、动态规划对比 |
| **错误描述** | 贪心每步选局部最优但累积不一定是全局最优。经典反例：硬币面值 [1, 3, 4] 找零 6 元，贪心选 4+1+1 共 3 枚，最优解为 3+3 共 2 枚。贪心找零在有特定硬币面值时"无法保证找到全局最优解，并且有可能找到非常差的解"。 |

## 图算法陷阱

### 38. DFS 递归深度等于 V 且无显式栈时栈溢出

| 字段 | 内容 |
|------|------|
| **书中位置** | 第9章 图 / 9.3 图的遍历 |
| **关联知识点** | DFS、递归深度、图遍历、visited |
| **错误描述** | 递归 DFS 的深度在最坏情况下等于顶点数 |V|（如链式图）。每次递归帧还需保存 visited 状态和当前邻接遍历进度。当 |V| 较大时栈溢出。 |
| **后果** | 程序崩溃。栈溢出前巨大空间消耗也压低性能。 |
| **正确做法** | （1）用显式栈实现非递归 DFS；（2）优先考虑 BFS 避免递归深度问题；（3）图的 DFS 尾递归改写对栈空间帮助有限。 |

### 39. BFS 最坏情况队列中保存 O(n) 个节点

| 字段 | 内容 |
|------|------|
| **书中位置** | 第7章 树 / 7.2 二叉树遍历 |
| **关联知识点** | BFS、层序遍历、队列空间复杂度 |
| **错误描述** | BFS 在层序遍历时队列需要同时保存当前层的所有节点。满二叉树时最底层有 n/2 个节点，队列空间 O(n)。书中："在最差情况下即满二叉树时遍历到最底层之前队列中最多同时存在 n/2 个节点空间复杂度为 O(n)。" |
| **后果** | BFS 的空间开销可能远大于 DFS（O(log n) 或有限递归深度），内存不足时不可用。 |
| **正确做法** | （1）空间有限时优先 DFS（O(h) 空间）；（2）需要最短路径特性时才必须用 BFS；（3）根据问题的空间时间需求选择搜索策略。 |

## 数值陷阱

### 40. 浮点数用双等号比较导致不可靠判断

| 字段 | 内容 |
|------|------|
| **书中位置** | 第10章 搜索 / 10.1 二分查找；第14章 动态规划 / 14.7 小结 |
| **关联知识点** | 浮点数精度、IEEE 754、容差比较 |
| **错误描述** | 浮点数 0.1+0.2 != 0.3（IEEE 754 精度问题）。用双等号比较浮点数可能得到错误结果，即使数学上应相等。二分查找中用浮点相等作为终止条件可能造成无限循环。 |
| **后果** | 条件判断失效；二分查找无限循环；几何计算和物理模拟产生累积误差导致结果错误。 |
| **正确做法** | （1）用容差比较：abs(a-b) < epsilon（如 1e-9）；（2）不用浮点相等作为循环终止条件；（3）精确计算用整数（如以分代元）或定点数库；（4）避免浮点数在等于判断中出现。 |

### 41. 浮点数 float 牺牲精度换取范围

| 字段 | 内容 |
|------|------|
| **书中位置** | 第3章 数据结构 / 3.3 数字编码 * |
| **关联知识点** | float、double、IEEE 754、数字编码 |
| **错误描述** | 书中指出：浮点数 float 虽然扩展了取值范围，但其副作用是牺牲了精度。整数类型 int 将全部 32 比特用于表示数字，而 float 将 32 比特分为符号位、指数位、有效数字位，有效精度仅约 7 位十进制数字。 |
| **后果** | 大数值运算中小数部分被吞没，累积误差逐渐放大。对需要高精度的金融计算或科学计算不可接受。 |
| **正确做法** | （1）精度优先用 double（约 15 位十进制精度）；（2）Dart 中默认为 double；（3）精确计算避免浮点用整数或 BigInt；（4）了解 float 和 double 的有效精度限制。 |

## 编码与表示陷阱

### 42. 原码不能直接用于运算

| 字段 | 内容 |
|------|------|
| **书中位置** | 第3章 数据结构 / 3.3 数字编码 * |
| **关联知识点** | 原码、反码、补码、数字编码 |
| **错误描述** | 原码虽然最直观（最高位符号位），但存在局限性：负数的原码不能直接用于运算。例如在原码下计算 1 + (-2) 得不到正确结果 -1。需要先判断符号、比较绝对值、确定结果符号、再执行加减，电路实现极其复杂。 |

## 堆算法陷阱

### 43. 堆操作复杂度被误认为 O(1)

| 字段 | 内容 |
|------|------|
| **书中位置** | 第8章 堆 / 8.1 堆 |
| **关联知识点** | 堆、堆化、完全二叉树、优先队列 |
| **错误描述** | 初学者常误以为堆的插入和删除是 O(1)（看起来只是往顶上放或拿走）。实际每次插入需自底向上堆化 O(log n)，每次删除堆顶需自顶向下堆化 O(log n)。建堆虽为 O(n)（自底向上 Floyd 方法）但非 O(1)。 |

## Dart 与工程实践陷阱

### 44. 循环中频繁拼接不可变字符串导致 O(n²)

| 字段 | 内容 |
|------|------|
| **书中位置** | 第4章 数组与链表 / 4.5 小结（涉及 Dart 实现） |
| **关联知识点** | Dart String、StringBuffer、不可变性 |
| **错误描述** | Dart 的 String 是不可变的，每次用加号拼接都创建新字符串并复制所有已有内容。在循环中 result += char 导致总时间复杂度 O(n²)：第 k 次拼接复制 k 个字符，n 次拼接共复制 n(n+1)/2 个字符。 |
| **后果** | 长度为 10^5 的字符串构建约 50 亿次字符复制，严重卡顿甚至看起来卡死。 |
| **正确做法** | （1）用 StringBuffer 进行循环中的字符串构建 O(n)；（2）用 List<String> 收集片段后用 join() 连接；（3）对已知片段数的构造用 StringBuffer(length) 预分配。 |

### 45. 循环不变量被破坏导致算法失败

| 字段 | 内容 |
|------|------|
| **书中位置** | 第10章 搜索 / 10.1 二分查找；第11章 排序 / 11.5 快速排序；第14章 动态规划 / 14.3 动态规划解题思路 |
| **关联知识点** | 循环不变量、正确性证明、初始化保持终止 |
| **错误描述** | 算法的循环不变量（初始化、保持、终止三阶段均须成立的命题）如果在某次迭代中被破坏，算法的正确性就无法保证。常见于二分查找的区间定义、快速排序的分区操作、插入排序的已排序区间、DP 的状态转移。 |
| **后果** | 看似跑通了但结果错误，且由于不变量被破坏错误极难定位和调试。 |
| **正确做法** | （1）显式定义关键循环的不变量；（2）确保初始化时成立；（3）确保每次迭代后保持；（4）确保循环终止时能推出正确结果；（5）二分查找为例：不变量为目标如果存在一定在当前区间内。 |
