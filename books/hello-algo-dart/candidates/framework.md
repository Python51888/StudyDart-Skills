## 一、学习与认知框架

### 1. 三段式算法学习路线
- **书中位置**：0.2.5
- **描述**：将算法学习分为三个递进阶段。阶段一（算法入门）：熟悉数据结构特点和算法原理，掌握基本用法和效率分析。阶段二（刷算法题）：积累至少 100 道题，按艾宾浩斯遗忘曲线周期性复习（3-5 轮重复形成长期记忆）。阶段三（搭建知识体系）：阅读专栏文章和算法教材，采用进阶策略（按专题分类、一题多解、一解多题），主动总结规律。
- **适用场景**：任何想系统学习算法的人，尤其面向求职的初学者。
- **书中例证**：本书内容主要覆盖"阶段一"，旨在帮助读者更高效地展开阶段二和阶段三。

### 2. 数据结构二维分类体系
- **书中位置**：3.1
- **描述**：从两个正交维度对所有数据结构进行分类。逻辑结构维度分为线性（数组、链表、栈、队列、哈希表，元素间一对一）和非线性（树、堆、图、哈希表，其中树形结构一对一多，网状结构多对多）。物理结构维度分为连续空间存储（数组）和分散空间存储（链表）。所有数据结构本质上都是数组或链表或二者的组合实现。
- **适用场景**：理解数据结构本质，帮助选择合适的数据结构实现方式。
- **书中例证**："基于数组可实现：栈、队列、哈希表、树、堆、图、矩阵、张量等。基于链表可实现：栈、队列、哈希表、树、堆、图等。"

### 3. "空间换时间"与"时间换空间"权衡原则
- **书中位置**：9.4（图章节小结）
- **描述**：数据结构的两种实现策略存在根本性的时空权衡。连续存储（数组）以空间换时间：内存紧凑、缓存友好、随机访问 O(1)，但增删 O(n)。分散存储（链表）以时间换空间：增删 O(1)、灵活扩容，但访问 O(n)、内存开销大（指针）。图的邻接矩阵是"空间换时间"的典型，邻接表则是"时间换空间"的代表。
- **适用场景**：任何需要在内存与速度之间做选择的场景。
- **书中例证**：邻接矩阵增删查效率高但空间 O(n^2)；邻接表节省空间但查边需遍历链表。

## 二、复杂度分析框架

### 4. 时间复杂度推算两步法
- **书中位置**：2.3.3
- **描述**：第一步：统计操作数量 T(n)，运用三个简化技巧——忽略常数项（与 n 无关的加数）、省略所有系数（2n→n）、循环嵌套时使用乘法。第二步：判断渐近上界，取 T(n) 中最高阶的项作为时间复杂度 O(f(n))，因为 n→∞ 时最高阶项起决定性作用。
- **适用场景**：手算任何算法的时间复杂度。
- **书中例证**：T(n)=2n(n+1)+(5n+1)+2=2n^2+7n+3，但简化统计只需关注 n^2，得 O(n^2)。

### 5. 时间复杂度排序谱系
- **书中位置**：2.3.4
- **描述**：七级时间复杂度从优到差排列：O(1) 常数阶 < O(log n) 对数阶 < O(n) 线性阶 < O(n log n) 线性对数阶 < O(n^2) 平方阶 < O(2^n) 指数阶 < O(n!) 阶乘阶。这是算法效率评价的"光谱"，是选择算法的首要依据。只要 n 足够大，低阶复杂度一定优于高阶，与常数系数无关。
- **适用场景**：快速判断算法效率等级，比较不同算法的理论性能。
- **书中例证**："算法 B 运行时间呈线性增长，在 n > 1000000 时比算法 C（常数阶但循环 1000000 次）更慢。只要 n 足够大，常数阶一定优于线性阶。"

### 6. 空间复杂度分析原则
- **书中位置**：2.4
- **描述**：空间复杂度衡量算法运行时的内存增长趋势，分为三类：输入空间（存储输入数据）、暂存空间（算法运行中的临时变量、栈帧、指令）、输出空间（存储输出数据）。分析时通常只统计暂存空间。递归深度导致栈帧空间累加，是常见陷阱——深度为 n 的递归空间复杂度至少 O(n)。
- **适用场景**：评估算法内存占用，在内存受限环境（嵌入式、移动端）下选择算法。
- **书中例证**：循环中新建变量为 O(1)，递归深度 n 为 O(n)，二维数组为 O(n^2)。

## 三、数据结构选择框架

### 7. 数组 vs 链表选择矩阵
- **书中位置**：4.1.2, 4.2, 4.5
- **描述**：数组优势在于空间效率高（连续内存无额外指针开销）、缓存命中率高（空间局部性）、随机访问 O(1)。链表优势在于插入删除 O(1)（无需移动元素）、长度动态可调、内存分配灵活（不要求连续大块空间）。选择依据：需要频繁随机访问或排序搜索 → 数组；需要频繁增删、长度不确定 → 链表；作为构建更复杂数据结构的基础 → 两者组合。
- **适用场景**：基础数据结构选型的第一道选择题。
- **书中例证**："由于数组具有更高的缓存命中率，因此它通常比链表更高效。在选择数据结构时，应根据具体需求和场景做出恰当选择。"

### 8. 栈与队列的选型指南
- **书中位置**：5.1-5.3, 5.4
- **描述**：栈（LIFO）：适用于需要"先入后出"逻辑的场景——浏览器后退、函数调用栈、括号匹配、表达式求值、DFS。队列（FIFO）：适用于需要"先入先出"逻辑的场景——任务调度、消息队列、BFS。双向队列：两端均可出入，适用于需要灵活操作两端的场景——滑动窗口、回文检查。三者均可用数组或链表实现；数组实现缓存友好但扩容开销大，链表实现灵活但指针开销多。
- **适用场景**：需要维护元素顺序且仅在特定端操作的场景。
- **书中例证**："栈如同叠猫猫，而队列就像猫猫排队。两者分别代表先入后出和先入先出的逻辑关系。"

### 9. 哈希表选择五条原则
- **书中位置**：6.4, 10.5.3
- **描述**：1) 需要 O(1) 快速查询 → 首选哈希表。2) 需要有序遍历或范围查询 → 不适合（哈希表无序）。3) 数据量极大 → 注意内存开销（哈希表有空位浪费）。4) 依赖哈希函数质量 → 劣质哈希函数导致 O(n) 退化。5) 负载因子（元素数/桶数）是关键参数，通常 0.75 触发扩容。链式地址适用于不确定数据量，开放寻址适用于内存敏感场景。
- **适用场景**：键值对存储、去重、缓存、查找表、计数。
- **书中例证**："哈希表的目标是将一个较大的状态空间映射到一个较小的空间，并提供 O(1) 的查询效率。"

### 10. 二叉搜索树 vs AVL 树的选择
- **书中位置**：7.4, 7.5, 7.6
- **描述**：二叉搜索树（BST）查找、插入、删除平均 O(log n)，但可能退化为链表（O(n)），适合数据随机插入或查询频率远大于更新频率的场景。AVL 树通过旋转操作（左旋、右旋、先左后右、先右后左）保持严格平衡，所有操作稳定 O(log n)，但旋转操作带来额外开销，适合需要频繁增删且要求稳定性能的场景。
- **适用场景**：需要有序存储且兼顾查找和更新效率的场景。
- **书中例证**："AVL 树从底向顶执行旋转操作，使树重新恢复平衡。"

### 11. 图的表示选择：邻接矩阵 vs 邻接表
- **书中位置**：9.2, 9.4
- **描述**：邻接矩阵用 n×n 矩阵表示边，增删查边 O(1)，但空间 O(n^2)，适合稠密图（边数接近 n^2）或需要快速判断任意两点连通性的场景。邻接表为每个顶点维护一个邻接列表，空间 O(n+m)，但查边需遍历列表 O(n)，适合稀疏图或内存受限场景。本质是"以空间换时间"（矩阵）和"以时间换空间"（表）的权衡。
- **适用场景**：社交网络（稀疏→邻接表）、电路网络（稠密→邻接矩阵）。
- **书中例证**："邻接矩阵体现了'以空间换时间'，邻接表体现了'以时间换空间'。"

## 四、算法策略选择框架

### 12. 搜索方法四象限选择
- **书中位置**：10.5.3, 10.6
- **描述**：四类搜索算法各有适用场景。线性搜索 O(n)：小数据量、单次查询、高频更新、无序数据，通用性最好。二分查找 O(log n)：有序数组、大数据量、低频增删、需要连续内存。哈希查找 O(1)：高频查询、无须范围查询、可接受额外空间开销。树查找 O(log n)：海量数据（内存分散）、需要有序性、支持范围查询。选择时需综合数据规模、查询频率、更新频率、内存限制四个维度。
- **适用场景**：任何需要从数据集中检索元素的场景。
- **书中例证**："线性搜索适用于小型或频繁更新的数据；二分查找适用于大型、排序的数据；哈希查找适用于对查询效率要求较高且无须范围查询的数据；树查找适用于需要维护顺序和支持范围查询的大型动态数据。"

### 13. 排序算法五维评价体系
- **书中位置**：11.1.1
- **描述**：评价排序算法的五个维度：1) 运行效率（时间复杂度及常数项大小）；2) 就地性（原地排序节省内存，数据搬运少速度更快）；3) 稳定性（相等元素相对顺序不变，是多级排序的必要条件）；4) 自适应性（利用已有顺序信息加速，最佳复杂度优于平均）；5) 是否基于比较（比较排序理论最优 O(n log n)，非比较排序可达 O(n) 但通用性差）。理想算法应具备前四个特性，但现实中不存在。
- **适用场景**：为具体排序任务选择合适的算法。
- **书中例证**："运行快、原地、稳定、自适应、通用性好。显然，迄今为止尚未发现兼具以上所有特性的排序算法。"

### 14. 排序算法综合对比与选型指南
- **书中位置**：11.11（图 11-19）
- **描述**：按类别三维选型。遍历排序（选择/冒泡/插入）：O(n^2)，原地，适合小数据量（插入排序因常数项小在业界极受欢迎，冒泡可加 flag 优化至自适应 O(n)）。分治排序（快速/归并/堆）：O(n log n)，快速排序实际最快但不稳定、可能退化 O(n^2)（用随机基准数缓解）；归并排序稳定但需 O(n) 辅助空间；堆排序原地但不稳定。线性排序（桶/计数/基数）：O(n)，但要求数据满足特定条件（范围有限、可表示为固定位数）。
- **适用场景**：小数据量用插入排序；通用场景用快速排序；要求稳定性用归并排序；内存紧张用堆排序；大数据量且取值范围小用计数/基数排序。
- **书中例证**：图 11-19 以矩阵形式对比 9 种排序算法的时间复杂度（最佳/平均/最差）、空间复杂度、稳定性、就地性、自适应性。

## 五、算法范式框架

### 15. 分治问题三条件判断法
- **书中位置**：12.1.1
- **描述**：判断一个问题是否适合分治的三个条件：1) 问题可分解——原问题能分解为规模更小、结构类似的子问题，且能以相同方式递归分解。2) 子问题独立——子问题之间没有重叠，互不依赖。3) 子问题的解可合并——通过合并子问题的解能构建原问题的解。三个条件缺一不可。归并排序完美满足：分→递归拆分数组，独立→各子数组独立排序，合并→合并有序数组。
- **适用场景**：归并排序、快速排序、二分查找、构建二叉树、汉诺塔、最近点对、大整数乘法等。
- **书中例证**："分：递归地将原数组划分为两个子数组，直到子数组只剩一个元素。治：从底至顶地将有序的子数组合并。"

### 16. 分治提升效率的双重原理
- **书中位置**：12.1.2
- **描述**：分治提升效率的底层逻辑有两条。其一，操作数量优化：将原问题等分为 k 份后，操作总数从 O(n^2) 降为 O(n^2/k + 2n)（常数项缩小），进一步递归分解可达 O(n log n)（如归并排序）。当 n > 4 时划分即有效。其二，并行计算优化：独立子问题可分配到多核并行处理（如桶排序：各桶分散到不同计算单元排序后合并），充分利用多核资源。
- **适用场景**：大数据量处理、多核/分布式场景。
- **书中例证**："为什么分治可以提升算法效率？这个问题可以从操作数量和并行计算两方面来讨论。"

### 17. 回溯算法通用框架代码
- **书中位置**：13.1.3
- **描述**：回溯算法的通用模板由四个核心步骤组成：1) 检查当前状态是否为解，若是则记录并（可选）返回。2) 遍历当前状态下的所有选择。3) 对每个选择先剪枝（判断是否合法），再尝试（做出选择，更新状态，递归），最后回退（撤销选择，恢复状态）。该框架将"尝试、回退、剪枝"三项核心操作标准化，只需根据具体问题定义 state、choices、isSolution、isValid、makeChoice、undoChoice 六个要素即可复用。
- **适用场景**：全排列、子集和、N 皇后、数独、图着色、组合优化等搜索问题。
- **书中例证**：框架代码以 `backtrack(State state, List<Choice>, List<State> res)` 为入口，内部通过 `isSolution→recordSolution→for(choices)→isValid→makeChoice→recurse→undoChoice` 的循环解决问题。

### 18. 回溯算法效率优化策略
- **书中位置**：13.1.5
- **描述**：回溯算法时间复杂度可达指数阶或阶乘阶，效率瓶颈在于状态空间过大。两大优化策略：1) 剪枝——利用约束条件提前终止无解的搜索分支，避免遍历无效搜索空间，是最有效的优化手段。2) 启发式搜索——引入估值函数或策略，优先搜索最可能产生有效解的路径（如 A* 算法）。剪枝是回溯的核心竞争力，合理的剪枝可将指数级搜索空间大幅压缩。
- **适用场景**：所有回溯问题，尤其是大规模状态空间问题。
- **书中例证**："剪枝可避免遍历无意义的搜索空间，从而提升搜索效率。"

### 19. 动态规划 vs 分治 vs 回溯三范式对比
- **书中位置**：14.2
- **描述**：三种范式都涉及子问题分解，但侧重点不同。分治：子问题相互独立，递归分解后合并解，无重叠。动态规划：子问题相互依赖（重叠），通过存储已解子问题避免重复计算。回溯：穷举所有可能的决策序列，通过剪枝排除无效分支，不要求合并。判断路径：问题是否满足决策树模型？→ 可用回溯。是否有大量重叠子问题？→ 考虑 DP。子问题是否独立且可合并？→ 考虑分治。
- **适用场景**：拿到一个新问题时，快速定位应该用哪种范式。
- **书中例证**："分治算法递归地将原问题划分为多个相互独立的子问题...动态规划中的子问题是相互依赖的...回溯算法在尝试和回退中穷举所有可能的解。"

### 20. 动态规划问题判断框架（加分项/减分项）
- **书中位置**：14.3.1
- **描述**：判断一个问题是否适合 DP 的实用方法。先判断是否满足"决策树模型"（问题能用树形结构描述，每个节点代表一个决策），若满足则可用回溯。再检查加分项：题目包含"最大/最小/最多/最少"等最优化描述；状态能用列表/矩阵/树表示且状态间存在递推关系。减分项（不适合 DP）：目标是找出所有方案（而非最优解）；有明显的排列组合特征需返回多个具体方案。满足决策树模型+加分项即可尝试 DP。
- **适用场景**：算法题和工程中的最优化问题。
- **书中例证**："如果一个问题满足决策树模型，并具有较为明显的'加分项'，我们就可以假设它是一个动态规划问题。"

### 21. 动态规划解题五步法
- **书中位置**：14.3.2
- **描述**：第一步，定义状态和 dp 表——将问题的决策变量抽象为状态（如网格中的 [i,j]），dp 表的每个维度对应一个独立变量。第二步，找出最优子结构——原问题的最优解如何从子问题的最优解构建。第三步，推导状态转移方程——用公式表达状态间的递推关系（如 dp[i,j]=min(dp[i-1,j],dp[i,j-1])+grid[i,j]）。第四步，确定边界条件和状态转移顺序——初始化 dp 表的首行/首列等边界，确保计算 dp[i] 时所有依赖的子状态都已算出。第五步，可选用"暴力搜索→记忆化搜索→动态规划"的开发路径。
- **适用场景**：所有动态规划问题的标准求解流程。
- **书中例证**：以"最小路径和"为例完整演练五步法，从定义二维 dp 矩阵到正序遍历实现。

### 22. 动态规划三大特性的内涵
- **书中位置**：14.2
- **描述**：1) 重叠子问题：递归分解中大量子问题重复出现，是 DP 诞生的原动力——通过存储避免重复计算，将指数级优化到多项式级。2) 最优子结构：原问题的最优解可由子问题的最优解构建——若不满足，DP 无法得出最优解，只能求可行解。3) 无后效性：给定状态后，其未来发展只与当前状态有关，与过往路径无关。若不满足（如"不能连续两轮跳 1 阶"的约束），可通过扩展状态定义（增加维度）来恢复无后效性；但严重有后效性的问题（每次决策影响全局约束）DP 难以解决。
- **适用场景**：判断 DP 是否适用，以及 DP 失效时的替代方案。
- **书中例证**：爬楼梯满足三大特性；添加"不能连续两轮跳 1 阶"约束后，扩展状态为 [i,j]（当前位置+上一轮跳的阶数）恢复无后效性；障碍生成问题每次跳跃改变全局约束，DP 难以解决。

### 23. "暴力搜索→记忆化搜索→动态规划"开发路径
- **书中位置**：14.1, 14.3
- **描述**：面对 DP 问题的推荐开发顺序。第一步暴力搜索（自顶向下递归）：理清子问题递推关系，验证决策树模型，时间复杂度通常 O(2^n)。第二步记忆化搜索：引入 mem 数组缓存已解子问题，剪枝重叠计算，复杂度降至 O(n) 或 O(nm)，编码量最小。第三步动态规划（自底向上迭代）：用循环替代递归，dp 表从最小子问题开始逐步构建，消除递归开销。可选第四步空间优化：观察当前状态仅依赖有限个前序状态时，用滚动变量消除 dp 数组维度，空间从 O(n) 降至 O(1)。
- **适用场景**：任何 DP 问题的开发过程，尤其适合初学者理清思路。
- **书中例证**：爬楼梯问题完整展示四步演变：回溯 O(2^n) → 记忆化 O(n) → DP O(n) → 滚动变量 O(1) 空间。

### 24. 贪心算法的判断与三步解题法
- **书中位置**：15.1.3, 15.1.2
- **描述**：贪心算法适用于同时满足两个条件的问题：贪心选择性质（局部最优→全局最优）和最优子结构（与 DP 共享）。解题三步：1) 问题分析——梳理状态定义、优化目标、约束条件。2) 确定贪心策略——找出每一步中能贪心地缩小问题规模的选择规则（如"优先选单位价值最高的物品"）。3) 正确性证明——用反证法或数学归纳法严格证明贪心策略的正确性（实践中常通过测试样例迭代验证）。贪心策略设计是核心难点，不同问题差异极大。
- **适用场景**：分数背包、区间调度、霍夫曼编码、Dijkstra、某些硬币组合的找零问题。
- **书中例证**："贪心算法仅用约十行代码就解决了零钱兑换问题——So clean！"

### 25. 贪心 vs 动态规划的核心区别
- **书中位置**：15.1
- **描述**：两者都依赖最优子结构，但决策方式根本不同。动态规划：综合考虑过去所有决策的影响，用过去子问题的解构建当前解，本质是"记忆的"——回顾过去。贪心算法：只看当前，不考虑历史决策，一路向前做贪心选择，本质是"健忘的"——只向前看。适用条件：DP 更通用但成本更高 O(n·amt)；贪心更高效 O(amt/min(coins)) 但条件苛刻，仅在问题具备贪心选择性质时保证最优。贪心不可靠时（如某些硬币组合的零钱兑换），必须用 DP。
- **适用场景**：面对优化问题时的第一道方法论选择。
- **书中例证**："动态规划会根据之前阶段的所有决策来考虑当前决策...贪心算法不会考虑过去的决策，而是一路向前地进行贪心选择。"

### 26. 哈希冲突解决策略对比
- **书中位置**：6.2, 6.4
- **描述**：两种主流策略各有优劣。链式地址（separate chaining）：每个桶存储一个链表，冲突元素追加到链表中，实现简单，不限制元素数量；缺点在于链表过长时查询退化 O(n)，可转化为红黑树优化（Java HashMap）。开放寻址（open addressing）：通过多次探测（线性探测固定步长、多次哈希用不同哈希函数）寻找下一个空位；缺点是不能直接删除元素（需标记删除），容易产生聚集（聚类效应降低效率）。Java 用链式地址，Python Dict 用开放寻址。
- **适用场景**：实现自定义哈希表时选择冲突解决策略。
- **书中例证**："链式地址通过将单个元素转化为链表...开放寻址通过多次探测来处理哈希冲突。线性探测使用固定步长，缺点是不能删除元素且容易产生聚集。"

### 27. 图遍历策略选择：BFS vs DFS
- **书中位置**：9.3
- **描述**：BFS（广度优先遍历）由近及远、层层扩张，用队列实现，适合找最短路径、层级遍历、社交网络中的"朋友的朋友"。DFS（深度优先遍历）一条路走到头再回溯，用递归/栈实现，适合拓扑排序、连通分量检测、迷宫求解、回溯算法的底层搜索。两者时间复杂度均为 O(|V|+|E|)，区别在于访问顺序和空间开销模式——BFS 需要维护队列存储当前层，空间可能很大；DFS 递归栈深度最多等于图的最长路径。
- **适用场景**：图的遍历和搜索问题。
- **书中例证**："队列具有'先入先出'的性质，这与 BFS 的'由近及远'的思想异曲同工。"

### 28. 递归树分析模型
- **书中位置**：14.1.1, 2.2
- **描述**：递归树（Recursion Tree）是将递归调用可视化为树形结构的分析工具。每个节点代表一次函数调用，边代表调用关系，树的深度等于递归深度，叶节点对应最小子问题（终止条件）。通过递归树可以直观看到：重叠子问题的来源（相同子树重复出现→DP 优化的机会）、时间复杂度估算（节点总数×每节点工作量）、空间复杂度估算（最大递归深度）。分治、回溯、DP 的暴力搜索解法都可通过递归树分析。
- **适用场景**：分析递归算法复杂度，识别重叠子问题。
- **书中例证**：爬楼梯 DP[9] 的递归树深度为 9，大量 DP[7]、DP[6] 重复出现，导致 O(2^n)。

### 29. 缓存局部性原理与数据结构选择
- **书中位置**：4.4, 4.5
- **描述**：CPU 缓存通过缓存行（cache line）、预取机制（prefetching）、空间局部性（相邻地址数据一起加载）和时间局部性（最近访问的数据很可能再次访问）来加速数据访问。连续存储的数组天然具有高缓存命中率，遍历数组时 CPU 可预测地预取整行数据。链表的分散存储导致缓存频繁失效，指针跳转打断预取机制。这意味着即使理论复杂度相同，数组实现的算法在实际运行中通常比链表实现更快。
- **适用场景**：高性能场景下的数据结构选择（如游戏引擎、高频交易）。
- **书中例证**："由于数组具有更高的缓存命中率，因此它通常比链表更高效。在选择数据结构时，应根据具体需求和场景做出恰当选择。"

### 30. 滚动变量空间优化技术
- **书中位置**：14.1.4
- **描述**：当 DP 的当前状态仅依赖前面有限个（通常 1-2 个）状态时，可以用滚动变量替代整个 dp 数组，将空间从 O(n) 压缩到 O(1)。本质是只保留必要的"历史快照"——每个新状态计算完成后，用变量赋值实现状态"滚动"。适用条件：状态转移方程只引用 dp[i-1]、dp[i-2] 等紧邻前序状态。此技术不仅用于 DP，也适用于斐波那契数列等任何满足递推关系且只需最近状态的计算。
- **适用场景**：所有满足"有限前序依赖"的递推计算。
- **书中例证**：爬楼梯中 dp[i] 仅依赖 dp[i-1] 和 dp[i-2]，用 a 和 b 两个变量滚动前进，空间 O(n)→O(1)。

### 31. 动态规划状态扩展技术（消除后效性）
- **书中位置**：14.2.2
- **描述**：当问题违反无后效性时（当前决策受历史影响），可通过"增加状态维度"来恢复无后效性。具体做法是将影响未来的历史信息编码为新的状态变量——如"不能连续两轮跳 1 阶"的爬楼梯问题，将状态从 [i]（当前位置）扩展为 [i, j]（当前位置 + 上一轮跳跃阶数），使 dp[i,1] 和 dp[i,2] 独立递推。代价是 dp 表维度增加，空间和时间复杂度相应提升。对于严重有后效性问题（如每一步改变全局约束），扩展状态也无法解决。
- **适用场景**：带约束的序列决策问题（如带冷却期的股票买卖、带限制的子序列问题）。
- **书中例证**：带约束爬楼梯的状态转移方程从一维变为二维：`dp[i,1]=dp[i-1,2]`；`dp[i,2]=dp[i-2,1]+dp[i-2,2]`。
